1 Executive Summary & Core Value Proposition

DocuChat AI is a state-of-the-art, 100% private Retrieval-Augmented Generation (RAG) platform designed to eliminate the two most critical pain points in modern document search:

1. The Hallucination & Provenance Crisis: Standard AI models either hallucinate or provide answers without verifiable evidence. Naive RAG systems highlight entire pages or 20+ unrelated boxes. DocuChat guarantees single-answer precision: it scores bounding boxes against the generated answer tokens and highlights only the exact supporting sentence on the native PDF canvas.
2. The Isolation Barrier (Dual Chat Mode): Most document tools trap users inside static PDFs. DocuChat features intelligent intent routing: when a document is active, it strictly grounds answers in document facts; when no document is active (or when broad world questions are asked), it seamlessly behaves like ChatGPT with live real-time web browsing (stocks, movies, sports, news) at zero API cost.

2.3 How to Stop, End, or Exit the Application

To safely shut down the application without leaving orphaned background processes:

  1. Stop Frontend: In Terminal 3, press Ctrl + C → type y → press Enter.
  2. Stop Backend: In Terminal 2, press Ctrl + C.
  3. Stop Docker Containers: In Terminal 1, run: 
    docker compose down
  4. Emergency Port Freeing (Windows PowerShell): If ports 5000 or 3000 remain held in the background: 
    Get-Process -Id (Get-NetTCPConnection -LocalPort 5000).OwningProcess -ErrorAction SilentlyContinue | Stop-Process -Force
Get-Process -Id (Get-NetTCPConnection -LocalPort 3000).OwningProcess -ErrorAction SilentlyContinue | Stop-Process -Force

3 Step-by-Step Project Lifecycle (From First to Last)

Every interaction follows a strictly engineered 10-step lifecycle. Below is the comprehensive breakdown of each step:

Step 01

Document Upload & Binary Persistence

api/routes/documents.py

The user drags a document (PDF, DOCX, TXT) into the left sidebar. The browser dispatches a multipart POST request to /api/documents/upload. The backend generates a secure UUID, writes the binary to backend/data/uploads/<uuid>_filename.pdf, and records a row in rag_app.db with status "processing".

Step 02

Structural Parsing & Coordinate Extraction

parsers/docling_parser.py

The parser decomposes the raw PDF into discrete layout blocks (headings, paragraphs, tables). If Docling is active, it runs deep layout analysis; otherwise, the local PyMuPDF (Fitz) engine executes. Crucial Innovation: Each text block extracts exact bounding coordinates (x0, y0, x1, y1, page_width, page_height, and coord_origin) and binds the exact sentence text directly to the box metadata.

Step 03

Structure-Aware Chunking

chunking/structure_chunker.py

Consecutive parsed elements are grouped into semantic chunks targeting ≈ 400 tokens with a 50-token rolling overlap. Table structures and section headers are preserved intact. All bounding boxes belonging to the elements in that chunk are aggregated inside chunk.bboxes.

Step 04

Dual Storage Indexing (Dense Vector + BM25Plus)

retrieval/pipeline.py & bm25.py

Each chunk is indexed in two distinct engines:
• Dense Vector: FastEmbed ONNX generates 384-dimensional embeddings (bge-small-en-v1.5) and stores them in Qdrant (doc_chunks collection).
• Sparse Lexical: BM25Plus indexes exact keywords and saves the inverted index to disk at backend/data/bm25/<doc_id>.json. Document status flips to "ready".

Step 05

User Query & Intent Routing

llm/router.py

The user submits a prompt via the chat textarea. QueryRouter inspects the active document scope and query intent:
• Document Scope Active: Dispatches to Hybrid Document Retrieval.
• No Scope / ChatGPT Mode: Dispatches to Real-Time Web Knowledge Engine.

Step 06

Hybrid Retrieval & Reciprocal Rank Fusion (RRF)

retrieval/pipeline.py

Parallel queries retrieve Top-30 dense vector hits from Qdrant and Top-30 lexical hits from BM25Plus. Scores are fused using Reciprocal Rank Fusion:
RRF_Score(d) = ∑ [ 1 / (60 + rank(d)) ]

Step 07

Reranking & Max-Scaling Score Calibration

retrieval/reranker.py

Candidate chunks are rescored. Key Solved Gotcha: Traditional min-max scaling forces the lowest candidate chunk to 0.0, causing valid secondary chunks (like project skills) to be discarded. DocuChat employs Max-Scaling (score / max_score), preserving all relevant chunks above the 0.25 threshold.

Step 08

Live Real-Time Web Knowledge Lookup

retrieval/web_search.py

If the user asks an off-topic or general question (stock prices, latest movies, sports standings, political news), DocuChat automatically queries Yahoo Finance, DuckDuckGo, and Wikipedia in real time, assembling fresh live context without requiring any paid API keys.

Step 09

Grounded LLM Streaming Generation (SSE)

llm/generator.py

Ollama (qwen2.5:1.5b) generates the response. Document chunks are passed with expanded 3,500-character windows. Strict system instructions enforce factual fidelity and require inline citations [1]. Tokens stream directly to the frontend over Server-Sent Events (SSE).

Step 10

Global Best-Box Scoring & Synchronized Highlighting

llm/generator.py & frontend/src/App.jsx

Upon generation completion, refine_citations_for_answer() extracts numeric and keyword tokens from the generated answer and evaluates all candidate bounding boxes across all chunks. Only the single highest-scoring box is returned. The frontend PDF.js canvas immediately scrolls to the page and illuminates that exact sentence with an animated glowing highlight.

5.2 Critical Engineering Gotchas Solved

Challenge Encountered Root Cause Analysis Engineered Solution
Context Truncation
(Skills cut off at "Oracle")		 generator.py had snippet = text[:900], arbitrarily truncating the chunk text at 900 characters. Expanded snippet budget to 3,500 characters per chunk, allowing full skill tables and projects to enter LLM context.
"Blue Screen" Over-Highlighting
(Entire PDF covered in blue)		 Parser attached all element bounding boxes to the chunk, and the backend passed all 20 boxes to the frontend. Engineered refine_citations_for_answer(): scores bounding boxes against answer tokens and passes only the single winning box.
BM25 Zero Keyword Hits
(No results on small resumes)		 BM25Okapi produces negative IDF scores when document frequency approaches corpus size, dropping candidate chunks. Upgraded to BM25Plus with lower-bounded positive IDF formulation.
Reranker Zeroing Dropoff
(Valid 2nd chunk discarded)		 Min-max normalization mathematically forces the second-best chunk to 0.0: (s - min)/(max - min). Replaced with Max-Scaling: norm = s / max_s. The second chunk preserves its true relative score and passes threshold.
Windows CP1252 Terminal Crash Wikipedia search returned phonetic symbols (IPA) that Windows console cannot encode in CP1252. Added clean_snippet() with html.unescape and unicode string sanitization.

The Senior ML / Full-Stack Engineer Deep Dive (For Architecture Reviews)

"DocuChat AI operates on a decoupled microservices architecture with FastAPI and React 18. During ingestion, documents are parsed by PyMuPDF/Docling into ParsedElement primitives carrying normalized (x0, y0, x1, y1) coordinates and explicit coordinate origins (TOPLEFT vs BOTTOMLEFT). Semantic chunking preserves header hierarchy paths. Retrieval executes parallel dense search via FastEmbed (bge-small-en-v1.5) and sparse lexical search via BM25Plus, combined via Reciprocal Rank Fusion ($k=60$). We replaced standard min-max rerank normalization with max-scaling ($s / \max s$) to avoid mathematically zeroing out valid secondary chunks. On the generation side, Qwen 2.5 (1.5B) streams SSE tokens. Post-generation, a global best-box scoring algorithm computes keyword and numeric overlap against the generated answer tokens, routing only the winning bounding box to the client. The frontend uses PDF.js on an HTML5 canvas to dynamically map the normalized bounding box with origin transformation."

7 What is Most Important (Key Takeaways)

1. Precise Single-Answer Highlighting (No "Blue Screen" Bug)

The system never highlights an entire paragraph, a whole chunk, or the entire page. It isolates the exact sentence or credential answering the question (e.g. "81% Narayana Junior College") and renders an animated glowing highlight directly on the PDF.js canvas.

2. Dual-Engine Intelligence (Strict Grounding vs Real-World Versatility)

When a document is active, the assistant acts as a strict compliance analyst: it cites facts inline with [1] and explicitly outputs "This is not mentioned in the document" if unstated. When no document is active or in ChatGPT mode, it acts as a conversational general assistant augmented with live stock market data and world news.

3. 100% Privacy & Zero API Cost

The entire pipeline runs on standard consumer laptop hardware without requiring subscriptions, credit cards, or paid API keys. All documents, embeddings, vector databases, and weights remain strictly on the local machine.

4. Production-Calibrated Hybrid Search Algorithms

By replacing BM25Okapi with BM25Plus and replacing min-max rerank normalization with Max-Scaling, the system avoids the common mathematical traps that cause small-corpus RAG systems to silently drop valid candidate chunks.
