3. Step-by-Step Order: When You Upload a PDF

This section details every single micro-step, the servers involved, the internal methods executed, and the models triggered from the moment a user selects a file in the browser to when it is indexed and ready for retrieval.

1
Frontend Selection & Multipart HTTP Dispatch
frontend/src/App.jsx Port 3000 -> 5000

What Happens: The user drops or selects a PDF file in the React UI. handleFileUpload(file) verifies the file existence, constructs a standard FormData object containing file, and sends an asynchronous POST http://localhost:5000/api/documents.

Calling Server: React Frontend on Port 3000.
Receiving Server: FastAPI Backend on Port 5000.
Active Code: App.jsx: lines 469–505.

2
FastAPI Upload Validation & Local Disk Staging
backend/api/documents.py FastAPI

What Happens: The endpoint upload_document() receives the upload. It checks the extension against ALLOWED_EXTENSIONS (.pdf, .docx, .pptx, .xlsx, .txt, .html, .png, .jpg). It generates a random UUID (doc_id = str(uuid.uuid4())) and streams the raw bytes to disk at backend/data/uploads/{doc_id}_{filename}.

Disk Location: backend/data/uploads/.
Active Code: documents.py: lines 92–113.

3
Database Row Creation & Background Task Enqueuing
PostgreSQL / SQLite backend/db/models.py

What Happens: A new DocumentModel entry is written to the database with status="processing", page_count=1, and chunk_count=0. FastAPI attaches process_document_background(doc_id, save_path, ext) to the BackgroundTasks queue and immediately returns HTTP 200 with the document metadata. The user’s browser does NOT freeze or wait.

Database Record: DocumentModel(id=doc_id, status="processing").
Active Code: documents.py: lines 114–131.

4
File Normalization & PDF Verification
backend/parsers/converter.py FastAPI Worker

What Happens: The background worker executes convert_to_pdf(file_path, settings.CONVERTED_DIR). If the uploaded file is already a .pdf, it immediately verifies page count using PyMuPDF (fitz.open()). If it is a .docx, .pptx, .xlsx, or image, it converts it to PDF using headless LibreOffice or PyMuPDF so the frontend can display it in the canvas viewer.

Output: A validated PDF file path saved at backend/data/converted/.
Active Code: converter.py: lines 9–83.

5
Docling Microservice Extraction (Server Call & AI Model)
Port 5000 -> 5001 Docling / TableFormer backend/parsers/docling_parser.py

What Happens: Backend calls docling_parser.parse_file(). It executes an HTTP POST http://localhost:5001/v1/convert/file sending the PDF binary to the Docling-serve microservice container. Docling runs its vision models (LayoutLM / DocLayNet / TableFormer) to detect paragraphs, section headers, tables, and exact bounding box coordinates: {"l": left, "t": top, "r": right, "b": bottom, "page_no": page}. Resilience Fallback: If the Docling Docker service is unreachable, DoclingParser automatically catches the exception and falls back to PyMuPDF (fitz) block extraction with zero crash.

Calling Server: FastAPI Backend (Port 5000).
Target Server: Docling-serve container (Port 5001).
Model Executed: Docling AI Document Parser & TableFormer.
Active Code: docling_parser.py: lines 41–184.

6
Structure-Aware Chunking with Provenance Retention
backend/chunking/structure_chunker.py

What Happens: structure_chunker.chunk_elements() receives the list of ParsedElement objects. Unlike naive token chunkers that cut words blindly, this chunker: 1. Keeps markdown tables intact inside isolated single chunks. 2. Respects section headers and titles (attaching heading_path). 3. Groups consecutive paragraphs to hit target 300–500 tokens. 4. Preserves 12% sliding window token overlap. 5. Accumulates all bounding boxes of every included paragraph inside the chunk metadata.

Output: A list of Chunk objects with full provenance.
Active Code: structure_chunker.py: lines 45–160.

7
Dense Vector Embedding Generation (AI Model)
BAAI/bge-small-en-v1.5 backend/embeddings/embedder.py

What Happens: embedder.embed_texts(chunk_texts) is called. It loads the BAAI/bge-small-en-v1.5 embedding model via FastEmbed (ONNX) or SentenceTransformers. It converts each text chunk into a normalized 384-dimensional floating-point vector. Fallback: If local sentence-transformers cannot load, it falls back to calling Ollama’s /api/embed endpoint.

Model Executed: BAAI/bge-small-en-v1.5 (384 dimensions).
Active Code: embedder.py: lines 38–62.

8
Vector Storage Upsert (Server Call & Indexing)
Port 5000 -> 6333 Qdrant Vector DB backend/retrieval/vector_store.py

What Happens: vector_store.upsert_chunks(chunks, vectors) prepares PointStruct objects containing the chunk ID, the 384-dimensional vector, and the JSON payload (chunk_id, doc_id, text, page, bboxes, heading_path). It executes an HTTP/gRPC upsert to Qdrant at http://localhost:6333 in collection doc_chunks.

Calling Server: FastAPI Backend (Port 5000).
Target Server: Qdrant Vector DB (Port 6333).
Active Code: vector_store.py: lines 53–80.

9
BM25Plus Lexical Inverted Indexing
backend/retrieval/bm25.py Disk: data/bm25

What Happens: bm25_index.add_document(doc_id, chunks) tokenizes all chunks, constructs an in-memory BM25Plus frequency index for exact keyword matching, and serializes the index to disk at backend/data/bm25/{doc_id}.json. This guarantees instant matching for technical acronyms, serial numbers, and names.

Disk Location: backend/data/bm25/{doc_id}.json.
Active Code: bm25.py: lines 49–66.

10
Relational DB Finalization & Frontend UI Active State
PostgreSQL / SQLite backend/api/documents.py React UI

What Happens: The background worker updates the database record: doc.status = "ready", doc.chunk_count = len(chunks), and commits the transaction. In the frontend, App.jsx polls GET /api/documents every 3 seconds, detects the status change from "processing" to "ready", and activates the document in the scope selector.

Active Code: documents.py: lines 79–85, App.jsx: lines 230–236.

4. Step-by-Step Order: When You Ask a Question / Chat

This section details what happens when a user types a query in the chatbox, hits Enter, and the system executes hybrid retrieval, reranking, LLM reasoning, streaming, and synchronized PDF highlighting.

1
User Message Input & SSE Streaming Post
Port 3000 -> 5000 frontend/src/App.jsx

What Happens: User types a message in the chat input. handleSendMessage() creates an optimistic message bubble in the UI, instantiates an AbortController, and initiates an HTTP POST http://localhost:5000/api/chat with payload: { conversation_id, message, document_ids, top_k: 5, fusion_method: "rrf", score_threshold: 0.25 }. The connection is opened as a text/event-stream (Server-Sent Events).

Active Code: App.jsx: lines 508–567.

2
Session Persistence & Conversation History Load
PostgreSQL / SQLite backend/api/chat.py

What Happens: The backend endpoint chat_endpoint() validates the incoming message. It creates or looks up the ConversationModel, saves a new MessageModel(role="user", content=message) to the database, and loads the last 6 conversation turns from the database for multi-turn contextual awareness.

Active Code: chat.py: lines 33–72.

3
Intent Routing: Document vs General ChatGPT Mode
backend/llm/router.py

What Happens: query_router.route_query() analyzes the query: 1. If no documents exist or the user selected scope "none", route is "general" ("General answer"). 2. If the user sent a pure greeting ("hi", "who are you", "thanks"), route is "general". 3. If documents are active and scoped, route is "document" ("From document").

Active Code: router.py: lines 13–43.

4
Multi-Query Rewriting & Pronoun Resolution (Server Call & AI Model)
Port 5000 -> 11434 Ollama (qwen2.5:1.5b) backend/llm/rewriter.py

What Happens: If route is "document", query_rewriter.transform_query() resolves ambiguities (e.g. "what is his experience?" -> "what is John Doe's software engineering experience?"). FastAPI calls Ollama at Port 11434 running qwen2.5:1.5b with a constrained JSON prompt. The LLM outputs a standalone query and 2 search variations.

Calling Server: FastAPI Backend (Port 5000).
Target Server: Ollama LLM Service (Port 11434).
Model Executed: qwen2.5:1.5b.
Active Code: rewriter.py: lines 13–71.

5
Parallel Hybrid Retrieval: Dense Vectors + Sparse BM25
Port 5000 -> 6333 bge-small-en-v1.5 backend/retrieval/pipeline.py

What Happens: For all generated query variations, retrieval_pipeline.retrieve() executes parallel searches using asyncio.gather: 1. Dense Vector Search: Query is embedded with bge-small-en-v1.5, and Qdrant (Port 6333) retrieves the Top 30 semantic matches filtered by doc_id. 2. Sparse BM25 Search: The BM25Plus index searches exact tokens and returns the Top 30 keyword matches.

Active Code: pipeline.py: lines 44–75.

6
Reciprocal Rank Fusion (RRF) & Deduplication
backend/retrieval/fusion.py backend/retrieval/dedup.py

What Happens: 1. reciprocal_rank_fusion() merges all ranking lists using RRF ($k=60$): $RRF(d) = \sum \frac{1}{60 + \text{rank}(d)}$. This brings passages matching BOTH semantic meaning and exact keywords to the top. 2. deduplicate_chunks() eliminates duplicates using chunk IDs and character 3-gram Jaccard similarity (0.88 threshold) to remove repetitive boilerplate.

Active Code: fusion.py: lines 3–35, dedup.py: lines 19–53.

7
Cross-Encoder Reranking (AI Model) & Threshold Filtering
BAAI/bge-reranker-base backend/retrieval/reranker.py

What Happens: The top 40 candidates are sent to reranker.rerank(). It evaluates each candidate with BAAI/bge-reranker-base using deep cross-attention: [Query, Passage Text]. It calculates precise relevance logits and normalizes them with a sigmoid function to $[0.0, 1.0]$. Passages with score $< 0.25$ are discarded. The final Top 5 highest-scoring passages are selected.

Model Executed: BAAI/bge-reranker-base (Cross-Encoder).
Active Code: reranker.py: lines 25–70, pipeline.py: lines 85–93.

8
Grounded Prompt Assembly & Streaming Generation (Server Call & AI Model)
Port 5000 -> 11434 Ollama (qwen2.5:1.5b) backend/llm/generator.py

What Happens: grounded_generator.build_grounded_prompt() formats the retrieved passages into numbered citation blocks: [1] (Page X): [Content]. It opens an HTTP streaming connection to Ollama at Port 11434 running qwen2.5:1.5b. As Ollama produces tokens, FastAPI yields Server-Sent Events (event: token\ndata: {"content": "..."}) straight to the browser in real time.

Calling Server: FastAPI Backend (Port 5000).
Target Server: Ollama LLM Service (Port 11434).
Model Executed: qwen2.5:1.5b.
Active Code: generator.py: lines 15–58, client.py: lines 45–83.

9
Real-Time Web Knowledge Fallback (If Document Lacks Answer)
backend/retrieval/web_search.py Web / Yahoo / DDG

What Happens: If the model outputs "This is not mentioned in the document" or retrieval returned 0 passages (e.g. asking for current NVDA stock price while viewing an employment contract), the engine automatically triggers live_web_search.get_live_context(). It queries Yahoo Finance or DuckDuckGo and streams real-world factual data under **Suggestions / Real-World Answer:**.

Active Code: web_search.py: lines 40–170, generator.py: lines 167–185.

10
Global Best-Box Refinement & Synchronized Canvas Highlighting
backend/llm/generator.py frontend/src/App.jsx PDF.js + Canvas

What Happens: 1. Backend runs refine_citations_for_answer(): It scores all candidate bounding boxes against the generated answer text. It finds the single winning bounding box containing the exact factual answer. 2. Backend emits event: citations with the winning box coordinate. 3. Frontend receives the event: It automatically opens the PDF viewer drawer, renders the exact page on an HTML5 <canvas> using PDF.js, and paints a fluorescent bounding box over the exact source line.

Active Code: generator.py: lines 197–264, App.jsx: lines 620–626 & 746–856.

6.2 Resiliency & Built-in Automatic Fallbacks

DocuChat is engineered with zero single-points-of-failure in local environments:

  • Docling Fallback: If the Docling-serve container is stopped or offline, docling_parser.py catches the connection error and automatically switches to PyMuPDF (fitz) structure extraction. No upload will ever fail.
  • Qdrant Fallback: If the Qdrant container is offline, vector_store.py automatically instantiates an embedded disk-backed Qdrant engine at data/qdrant_storage, or an in-memory client.
  • SentenceTransformers / Embedder Fallback: If HuggingFace packages fail, embedder.py falls back to calling Ollama’s native /api/embed endpoint.
  • Document Not Mentioned Fallback: If the user asks a real-world question (e.g. "what is the latest price of Nvidia stock?") while a document is loaded, the system detects that the facts are absent from the document, states "This is not mentioned in the document", and automatically fetches live Yahoo Finance and DuckDuckGo web results.
Operational Summary: DocuChat AI delivers enterprise-grade grounded document intelligence with zero hallucinations, complete PDF provenance, full offline privacy, and live real-world knowledge capabilities across all files in its unified architecture.
